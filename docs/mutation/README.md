## Какие изменения проверял инструмент

Использованы стандартные включённые операторы Gremlins и дополнительный `INVERT_LOGICAL`. В текущем коде они сформировали:

- 23 мутации `CONDITIONALS_NEGATION`: замена `==` на `!=` и обратно;
- 3 мутации `INVERT_LOGICAL`: замена `&&` на `||` и обратно.

Примеры пойманных мутаций:

- В `Trip.Finish` условие `Status != StatusActive` заменяется на `==`. Тесты успешного завершения и отклонения завершённой поездки обнаруживают нарушение перехода статуса.
- В `NewTripStatusChange` инвертируются проверки `fromStatus` и `reason` на `nil`. Тесты конструктора обнаруживают потерю значений или панику.
- В создании поездки инвертируются проверки наличия ключа и результата сравнения SHA-256. Тесты идемпотентности обнаруживают неверную обработку повтора или конфликта.
- В usecase инвертируются проверки ошибок репозитория и записи истории. Сценарии ошибок обнаруживают неверный результат и нарушение ожидаемой последовательности вызовов.

Мутации не проверяют каждое возможное изменение кода: например, при этих операторах замена одного строкового литерала статуса другим не генерируется. Отсутствие выживших относится к перечисленным 26 мутациям.

## Повторение в Linux

Из корня репозитория:

```bash
go install github.com/go-gremlins/gremlins/cmd/gremlins@v0.6.0
"$(go env GOPATH)/bin/gremlins" unleash ./internal/domain \
  --workers 2 --timeout-coefficient 10 --invert-logical \
  --output docs/mutation/domain-current.json --output-statuses lct
"$(go env GOPATH)/bin/gremlins" unleash ./internal/usecase \
  --workers 2 --timeout-coefficient 10 --invert-logical \
  --output docs/mutation/usecase-current.json --output-statuses lct
```

Для сохранённых прогонов использованы те же аргументы; имена файлов – `domain-before.json`, `usecase-before.json`, `domain-after.json`, `usecase-after.json`. Исходные файлы проекта Gremlins мутирует во временной копии.
